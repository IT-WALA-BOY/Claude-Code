# Code standards

These rules apply to every line of the PHP build. Any AI tool or person writing code for this project reads this file first. They come from current guidance on prompting AI for clean code (keep the rules in the repo, work in small tested chunks, review each chunk before the next) and from web.dev's animation performance guidance.

## Goals, in order
1. **Correct and safe.** Single admin, private data.
2. **Fast.** Every page renders on the server in under 50 ms and is usable before any JS runs.
3. **Smooth.** Every interaction answers in under 100 ms and every animation runs at 60 fps.
4. **Easy to read.** A new person can find and change any screen in minutes.

## Stack (no build step)
- PHP 8.1+, PDO MySQL, no framework, no Composer.
- Plain CSS with custom properties from `assets/css/tokens.css`.
- Vanilla JS ES modules. **No libraries.** Drag and drop, charts and calendars are small in-house modules.
- Charts are SVG rendered by PHP. JS adds only tooltips.
- Icons: one Lucide SVG sprite (`assets/icons.svg`), generated by `tools/build-icons.mjs`.
- Font: self-hosted Inter variable (with the optical size axis, so large text uses the Display cut).

## Structure
- `index.php` is the only entry point for pages and the API. `install.php` runs once.
- `app/` holds PHP logic: `core/` (db, auth, csrf, http, view), `lib/` (format, time, charts), `repo/` (one file of queries per module), `api/` (one file of JSON handlers per module).
- `pages/` holds one template per screen. `partials/` holds the shell and shared pieces.
- A page template only reads data from a repo function and prints it. No SQL in templates.
- A repo function only talks to the database. No HTML in repos.
- `assets/js/app.js` is the shared runtime (API calls, dialogs, menus, toasts, soft refresh). `assets/js/pages/*.js` holds one module per screen and exports `init(root)`.

## PHP rules
- `declare(strict_types=1);` in every file. Type every parameter and return value.
- Prepared statements only. Never put a variable inside SQL text.
- Escape every value printed into HTML with `e()`. Never echo raw user input.
- Every API write checks the CSRF token and the session. GET requests never change data.
- Functions are short and named by what they return or do: `tasks_due_today()`, `money_usd()`.
- No dead code, no commented-out code, no debug output.
- Money is stored as DECIMAL(12,2) with its currency. Times are stored as Pacific wall time.

## JS rules
- One job per module. No globals except the `app` runtime.
- **Optimistic UI:** update the DOM first, send the request, roll back and show a toast if it fails.
- Use event delegation on the page root instead of one listener per row.
- Read layout (getBoundingClientRect) before writing styles, never interleaved in a loop.
- Pointer events for drag (works for mouse, pen and touch). `requestAnimationFrame` for per-frame work.

## Motion rules (buttery smooth)
- **Animate only `transform` and `opacity`.** Never animate width, height, top, left, margin or box-shadow on large areas.
- Durations: 120 ms for hovers and presses, 180 ms for menus and dialogs, 200 ms maximum otherwise.
- Easing: `cubic-bezier(.2,.8,.2,1)` for entering, `cubic-bezier(.4,0,1,1)` for leaving.
- Drag: the card lifts (scale 1.02, rotate 2deg, `Shadow/Drag`) and a dashed placeholder marks the drop spot. Other cards slide into place using FLIP (transform only).
- Page changes use cross-document View Transitions (a short fade of the main panel). The sidebar stays still.
- Links prerender on hover through Speculation Rules, so pages open instantly in Chromium browsers.
- Respect `prefers-reduced-motion`: turn motion off, keep the state change.
- Banned: parallax, card entry animations, bouncing, spinners where a skeleton fits.

## UI rules
- Follow `docs/design-rules.md` for tokens, copy and states. No em dashes in any string.
- Every data surface has 4 states: empty, loading, error, populated.
- Every button and link has a visible focus ring. Every icon-only button has an `aria-label`.
- Tap targets are at least 32 px. Keyboard: `Esc` closes, `/` or `Cmd K` focuses search, `N` adds a task.

## Workflow for each chunk
1. Build one screen or one module.
2. Run `php -l` on every changed PHP file.
3. Open it in the browser (Playwright), click through it, check the console for errors.
4. Compare with the Figma screen.
5. Re-read the diff for dead code, duplication and missing escapes. Then commit.
